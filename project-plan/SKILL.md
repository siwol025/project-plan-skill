# 대화형 프로젝트 기획서 작성

기획서를 한 번에 완성하지 않는다. 항목 하나를 사용자와 대화로 확정한 뒤 다음 항목으로 간다.

## 목차 (고정 순서)

1. 개요
2. 왜 이 프로젝트/서비스가 필요한가?
3. 이 프로젝트와 유사한 구현 사례
4. 사용 사례 식별 및 프로젝트 필요성 평가
5. 요구사항 수집 및 분석
6. 기술스택 결정 및 트레이드오프 비교
7. 아키텍처 및 기능별 파이프라인
8. 기능목록

각 항목에 필요하면 하위 항목(`###`, `####`)을 자유롭게 만든다.

## 시작 절차

1. 프로젝트 이름과 한 줄 설명을 묻는다.
2. 현재 작업 폴더에 `기획서_<프로젝트명>.md`가 있는지 확인한다.
   - 없으면: 제목과 8개 항목 헤더(`## 1. 개요` …)만 있는 뼈대를 만든다. 각 본문은 `_(작성 전)_`.
   - 있으면: 읽고, 확정된 항목을 요약한 뒤 첫 미완성 항목부터 이어간다.
3. 진행 순서를 짧게 안내하고 1번 항목을 시작한다.

## 항목별 진행 루프

한 항목이 확정되기 전에는 다음 항목으로 넘어가지 않는다.

1. **정보 수집**: 아래 "필요 정보 체크리스트"의 모든 칸이 채워질 때까지 질문을 계속한다.
   - 질문 수에 제한이 없다. 한 번에 몇 개씩 묶어서 묻는다.
   - 답이 모호하거나 빠진 정보가 있으면 후속 질문한다.
   - 앞서 확정한 항목에서 이미 알 수 있는 것은 다시 묻지 않는다. 대신 "앞서 ~라고 하셨는데 맞나요?"처럼 확인만 한다.
   - 사용자가 "모르겠다"고 하면 선택지나 추천안을 제시해 고르게 한다.
2. **초안 제시**: 체크리스트가 다 채워지면 해당 항목 초안을 채팅에 보여준다. 필요한 하위 항목 구성도 함께 제안한다.
3. **검토**: 사용자가 수정을 요청하면 반영해 다시 보여준다.
4. **확정·저장**: 사용자가 확정하면 파일에서 해당 항목 섹션만 갱신한다. 다른 섹션은 건드리지 않는다.
5. **다음으로**: "다음 항목(N. 이름)으로 넘어갈까요?"로 끝낸다.

사용자는 언제든 항목을 건너뛰거나, 이전 항목으로 돌아가 수정할 수 있다. 이전 항목을 고치면 영향 받는 뒤 항목이 있는지 알려준다.

## 항목별 가이드

### 1. 개요
- 체크리스트: 프로젝트 배경, 목표(정량 목표 포함 가능), 대상 사용자, 범위(포함/제외), 기간·팀 규모(있으면)
- 권장 하위 항목: 배경 / 목표 / 대상 사용자 / 범위

### 2. 왜 이 프로젝트/서비스가 필요한가?
- 체크리스트: 해결하려는 문제, 문제를 겪는 사람과 상황, 현재 해결 방식과 그 한계, 해결 시 기대 효과
- 권장 하위 항목: 문제 정의 / 기존 방식의 한계 / 기대 효과

### 3. 이 프로젝트와 유사한 구현 사례
- 체크리스트: 사용자가 아는 유사 서비스, 각 사례의 핵심 기능·장단점, 우리 프로젝트의 차별점
- 사용자가 원하면 WebSearch로 사례를 조사한다. 조사 결과에는 출처 링크를 단다.
- 권장 형식: 사례 비교표(서비스명 | 주요 기능 | 장점 | 한계 | 우리와의 차이) + 차별화 포인트

### 4. 사용 사례 식별 및 프로젝트 필요성 평가
- 체크리스트: 주요 페르소나, 핵심 사용 시나리오, 각 시나리오의 빈도와 불편 정도, 대안 존재 여부
- 권장 하위 항목: 페르소나 / 유스케이스 시나리오 / 필요성 평가표(시나리오 | 빈도 | 고통도 | 대안 | 평가)

### 5. 요구사항 수집 및 분석
- 체크리스트: 기능 요구사항, 비기능 요구사항(성능·보안·가용성·확장성 등), 우선순위, 제약조건(예산·기간·기술·법규)
- 권장 하위 항목: 기능 요구사항(ID 부여, 예: FR-01) / 비기능 요구사항(NFR-01) / 우선순위(MoSCoW) / 제약조건

### 6. 기술스택 결정 및 트레이드오프 비교
- 체크리스트: 필요한 기술 영역(프론트엔드·백엔드·DB·인프라·AI 등), 팀이 익숙한 기술, 영역별 후보, 선택 기준(비용·성능·학습곡선·생태계 등)
- 후보를 추천할 때는 5번 요구사항과 연결해 근거를 댄다.
- 권장 형식: 영역별 후보 비교표 + 최종 선택과 근거 + 감수하는 트레이드오프

### 7. 아키텍처 및 기능별 파이프라인
- 체크리스트: 주요 구성요소, 구성요소 간 통신 방식, 외부 연동, 배포 환경, 핵심 기능별 데이터 흐름
- 권장 하위 항목: 전체 아키텍처(Mermaid 다이어그램) / 기능별 파이프라인(기능마다 단계별 흐름 + Mermaid)

### 8. 기능목록
- 체크리스트: 전체 기능 목록, 각 기능의 우선순위, 관련 요구사항 ID, 개발 단계(MVP/이후)
- 앞 항목에서 나온 기능을 먼저 모아서 보여주고, 빠진 기능이 있는지 묻는다.
- 권장 형식: 표(ID | 기능명 | 설명 | 우선순위 | 관련 요구사항 | 단계)

## 규칙

- 사용자 확인 없이 항목을 확정하거나 파일에 쓰지 않는다.
- 사용자가 말하지 않은 내용을 넣을 때는 `(가정)`을 붙이고 확인을 받는다.
- 8개 항목이 모두 확정되면 파일 경로와 항목별 한 줄 요약을 알려준다.
